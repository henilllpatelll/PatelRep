  <name>Task 1: Build the AST introspection engine (role constants + route/dependency extraction)</name>
  <files>apps/api/scripts/generate_rbac_matrix.py</files>
  <action>
Create `apps/api/scripts/generate_rbac_matrix.py`. Use Python's built-in `ast` module only (stdlib — no new dependency, matches the enum-drift-guard precedent's zero-dependency style). Do NOT import or execute router modules — parse their source text as AST only, so the script never needs env vars, Supabase credentials, or a running app.

Module docstring at the top must state the single command to regenerate the artifact: `python apps/api/scripts/generate_rbac_matrix.py` (run from `apps/api/`, or works via absolute paths regardless of cwd since all paths are derived from `Path(__file__)`).

Build these pieces, in order:

1. **`parse_role_constants(roles_path: Path) -> dict[str, tuple[str, ...]]`** — parse `apps/api/core/roles.py` with `ast.parse`. For each top-level `Assign` where the value is a `Tuple`/`List`/`Set` of string `Constant`s, or a `Name` referencing an already-parsed constant (handles `ALL_STAFF_ROLES = ALL_ROLES`), record `{constant_name: tuple_of_role_strings}`. This is the canonical constant table (`ALL_ROLES`, `ALL_STAFF_ROLES`, `MANAGER_ROLES`, `PROGRAM_MANAGER_ROLES`).

2. **`parse_api_prefix(main_path: Path) -> str`** — parse `apps/api/main.py`, find the top-level `PREFIX = "..."` assignment via AST, return its literal value (currently `/v1`). Do not hardcode `/v1` — derive it, so the matrix stays correct if the prefix ever changes.

3. **Per-router constant resolution** — for each router file, before walking routes: (a) scan `ImportFrom` nodes where `module` ends with `core.roles` (or `.roles`) or module is exactly `roles`/`core.roles`, collecting imported names and mapping them to the `core.roles` table from step 1; (b) scan top-level `Assign` nodes in the router file itself the same way as step 1 for locally-defined constants (e.g. `SESSION_ROLES`, `SHIFT_ROLES`, `SUPERVISOR_ROLES`, `EVIDENCE_CAPTURE_ROLES`, `COMPETENCY_MANAGER_ROLES`). Merge into one `{name: tuple[str,...]}` map per file (imported core.roles names + local names; local names win on collision since that's what the router actually uses).

4. **`get_router_prefix(tree: ast.Module) -> str`** — find the `router = APIRouter(...)` call, extract the `prefix=` keyword's string literal (every router file in this codebase sets one — see `apps/api/routers/*.py` line ~10-40 pattern `router = APIRouter(prefix="/xyz", tags=[...])`).

5. **Route + gate extraction** — walk the module body for top-level `AsyncFunctionDef`/`FunctionDef` nodes decorated with `@router.get(...)`, `.post(...)`, `.put(...)`, `.patch(...)`, or `.delete(...)` (confirmed: no `@router.api_route` usage exists in this codebase, so only these 5 verbs need handling). For each:
   - `method` = the decorator's attribute name, uppercased.
   - `route_path` = the decorator call's first positional string argument.
   - `full_path` = `api_prefix + router_prefix + route_path` (e.g. `/v1/rooms/{room_id}/undo`).
   - Scan the function's parameters for a default value shaped `Depends(require_role(...))`. If found: for each argument inside the inner `require_role(...)` call, resolve `Constant` strings directly, and `Starred(value=Name(id=X))` by looking up `X` in the per-router constant map from step 3 (fall back to the literal name with a `(unresolved)` marker if not found — must never silently drop a role). Record `required_roles` = the resolved tuple, and `source` = `ast.unparse()` of the `require_role(...)` call plus its line number, e.g. `require_role(*PROGRAM_MANAGER_ROLES) [L121]`.
   - If no `require_role` dependency param exists, check for other named dependencies on `current_user`/`hotel_user` params (`Depends(get_current_user)`, `Depends(get_current_user_no_hotel)` — the actual dependency names used in `apps/api/middleware/auth.py`) and record which one, since that determines whether "no role gate" means "any authenticated staff" vs "pre-tenant bootstrap". Note: `internal.py`'s cron endpoints do NOT use a `Depends(...)`-wired auth check — they take `x_cron_secret: str = Header(None)` as a plain parameter default and call `verify_cron(x_cron_secret)` (defined in `internal.py` itself) as a plain function call inside the handler body. Detect this by walking the function body (`ast.walk`) for a `Call` node whose func is `Name(id="verify_cron")`; if found, record `required_roles_display = "N/A (not role-based)"` and `source = "verify_cron(...) [L{lineno}]"` instead of falling through to the generic no-dependency case — this makes the classification intentional and gives those ~13 rows a real source annotation instead of an empty one.
   - Separately, walk the full function body (`ast.walk`, not just top level) for `Compare` nodes whose left side is an `Attribute` matching `<name>.role` (i.e. attr == "role", e.g. `current_user.role`) using `==`, `!=`, `in`, or `not in`. For each match, resolve the comparator the same way as require_role args (Constant, Tuple/List/Set of Constants, or Name via the constant map) and record as an "inline check" note with its line number — these are the object-level/business-rule checks Phase 19's RBAC-AUDIT.md classified separately from route-level gates. A route can have both a route-level gate AND inline checks (e.g. `late_checkout.py`).
   - `required_roles_display`: if a `require_role` gate was found, render its resolved roles (comma-joined, sorted). If NOT found but the dependency was `get_current_user`/`get_current_user_no_hotel` (no role restriction), render `"none"`. If NOT found and the dependency was `verify_cron` or no `current_user`-shaped dependency exists at all (e.g. `webhooks.py`, which verifies provider signatures inline in the handler body, not via a FastAPI dependency), render `"N/A (not role-based)"`.

Do not execute this task's verification by running the full script yet — that belongs to Task 2. Prove this piece works by writing a small `if __name__ == "__main__":` block that, for now, just parses `apps/api/core/roles.py` and one router file (e.g. `apps/api/routers/programs.py`, which exercises both `PROGRAM_MANAGER_ROLES` starred-constant gates and multiple decorators) and prints the extracted rows, then manually inspect the output against `programs.py`'s known gates (lines 121,188,220,249,283,289,301,321,328,335,342,349 per RBAC-AUDIT.md) before moving to Task 2.
  </action>
  <verify>`cd apps/api && .venv\Scripts\python.exe scripts/generate_rbac_matrix.py` (with the temporary programs.py-only main block) prints rows whose required-roles match RBAC-AUDIT.md's documented `programs.py` gates (PROGRAM_MANAGER_ROLES resolving to `("gm","housekeeping_supervisor","engineer","chief_engineer")`, plus the narrower `require_role("gm")` / `require_role("gm","chief_engineer")` / `require_role("housekeeper","housekeeping_supervisor","gm")` sites).</verify>
  <done>parse_role_constants, parse_api_prefix, and the per-router extraction pipeline correctly resolve both inline string-literal require_role() calls and starred core.roles/local constant references, proven against apps/api/routers/programs.py.</done>
