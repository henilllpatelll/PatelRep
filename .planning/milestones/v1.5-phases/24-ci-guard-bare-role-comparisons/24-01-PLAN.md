<objective>
Add a second, narrower CI guard on top of Phase 23's RBAC-MATRIX drift guard: fail the build when a router file in `apps/api/routers/` contains a "bare" role comparison -- `current_user.role == "..."`, `in {...}`, `not in {...}`, etc. -- that is neither a `require_role(...)` call (route-level gates are fine, they're already tracked by Phase 23) nor sourced from a constant imported from `apps/api/core/roles.py` (the canonical single source of truth). Every bare comparison already in the codebase today (confirmed correct by Phase 19's `RBAC-AUDIT.md` review and Phase 23's CR-01 fix) is captured in a checked-in, per-entry-reasoned allowlist, so the guard enforces "no *new* drift," not "retroactively rewrite everything."

Purpose: RBAC-AUDIT.md's RBAC-03 review already found and closed 2 real gaps in `lost_found.py` because inline role checks are easy to add correctly once and then silently miss on the next similar route. This phase turns "did you remember to route this through `require_role()` or a `core/roles.py` constant" into a build failure instead of a code-review hope.
Output: `apps/api/scripts/check_bare_role_comparisons.py` (detector, reuses Phase 23's constant-parsing), `apps/api/rbac_bare_comparison_allowlist.json` (the RBAC-08 allowlist), `apps/api/tests/smoke/test_bare_role_comparison_guard.py` (the RBAC-07 CI enforcement, picked up automatically by `ci.yml`'s existing `python -m pytest tests/smoke/ -v --tb=short` step -- no workflow file changes needed).
</objective>

  <name>Task 1: Build the bare-role-comparison detector (whole-module AST scan + core.roles-import provenance)</name>
  <files>apps/api/scripts/check_bare_role_comparisons.py</files>
  <action>
Create `apps/api/scripts/check_bare_role_comparisons.py`. Stdlib `ast` only, same zero-dependency style as `generate_rbac_matrix.py` and `test_enum_contracts.py` -- no imports of router code, no env vars needed. Module docstring states the two ways to run it: as a standalone report (`python apps/api/scripts/check_bare_role_comparisons.py`, prints every un-allowlisted bare comparison and exits 1 if any exist) and as the engine behind `apps/api/tests/smoke/test_bare_role_comparison_guard.py`.

This detector is deliberately **broader in scope** than `generate_rbac_matrix.py`'s per-route inline-check scan: it walks the **entire router module** (`ast.walk(tree)`, not just the bodies of `@router.<verb>(...)`-decorated functions), because real bare role checks live in module-level helper functions too -- e.g. `work_orders.py`'s `_ensure_engineer_can_update_work_order` (line 38) and `_ensure_engineer_can_complete_work_order` (line 66), and `rooms.py`'s `_validate_undo_permission` (lines 51, 55), neither of which is itself a route handler. Do not restrict the walk to decorated functions.

Load `apps/api/scripts/generate_rbac_matrix.py`'s `parse_role_constants` via `importlib.util.spec_from_file_location` + `exec_module` (same pattern `test_rbac_matrix_contract.py` already uses) -- do not re-derive core.roles constant parsing; reuse it so the two scripts can never classify `core/roles.py` differently.

Build these pieces:

1. **`imported_core_roles_names(tree: ast.Module, core_roles: dict[str, tuple[str, ...]]) -> set[str]`** -- scan only the router file's top-level `ImportFrom` nodes where `module` is `roles`, `core.roles`, or ends with `.roles` (same module-matching condition as `generate_rbac_matrix.py`'s `_resolve_router_constants`, but do NOT merge in the router's own locally-defined `Assign` constants -- that's the whole point of this function: it answers "was this name *imported from core/roles.py*", not "is this name a known constant at all"). For each matching import, if `alias.name` is a key in `core_roles`, add `alias.asname or alias.name` to the result set. A locally-defined router constant like `guest_requests.py`'s `MESSAGE_ROLES` or `rooms.py`'s `UNDO_ALL_ROLES` must NOT appear in this set even though `generate_rbac_matrix.py`'s merged constant map would resolve it fine for display purposes -- RBAC-07 explicitly requires the source to be an *imported core/roles.py constant*, not just "any known name."

2. **`find_bare_role_comparisons(router_path: Path, core_roles: dict[str, tuple[str, ...]]) -> list[dict]`** -- parse the file, compute `imported_core_roles_names` for it, then `ast.walk` the whole module for `ast.Compare` nodes where: `node.left` is an `ast.Attribute` with `attr == "role"` (matches the existing convention in `generate_rbac_matrix.py`'s inline-note scan -- do not attempt to handle `.role` on the right-hand side or chained calls like `.role.lower()`; none exist in the codebase today, note this as a known limitation in the module docstring, mirroring the WR-02 limitation note style already in `generate_rbac_matrix.py`), and `node.ops[0]` is one of `ast.Eq`, `ast.NotEq`, `ast.In`, `ast.NotIn`. For each match:
   - If the single comparator (`node.comparators[0]`) is an `ast.Name` whose `id` is in `imported_core_roles_names` for this file -> **skip it, not bare** (it's properly sourced from `core/roles.py`).
   - Otherwise -> it's bare (this covers: a literal string `"gm"`, a literal `Tuple`/`List`/`Set` of strings, and a `Name` referring to a locally-defined-in-router constant like `MESSAGE_ROLES`/`SUPERVISOR_ROLES`/`UNDO_ALL_ROLES` -- none of those are "sourced from an imported core/roles.py constant"). Record `{"router": router_path.name, "line": node.lineno, "code": ast.unparse(node)}`.

3. **`load_allowlist(allowlist_path: Path) -> set[tuple[str, str]]`** -- read the JSON file (schema: `{"entries": [{"router": ..., "line": ..., "code": ..., "reason": ...}, ...]}`), return a `set` of `(entry["router"], entry["code"])` pairs. Matching is by `(router filename, exact ast.unparse text)`, **not** by line number -- deliberately, so the allowlist survives unrelated edits elsewhere in the file (e.g. adding an import above shifts every line number below it; a strict line-number match would make the guard flag every pre-existing check as "new" on the next unrelated commit, which is a worse failure mode than the drift it's meant to catch).

4. **`find_violations(api_root: Path, allowlist_path: Path) -> list[dict]`** -- `core_roles = parse_role_constants(api_root / "core" / "roles.py")` (via the imported `generate_rbac_matrix` module), glob `apps/api/routers/*.py` excluding `__init__.py`, sorted alphabetically (same determinism convention as `generate_rbac_matrix.py`), run `find_bare_role_comparisons` per file, load the allowlist, and return every bare-comparison dict whose `(router, code)` is NOT in the allowlist set. Sort violations by `(router, line)` for stable, readable output.

5. **`main()`** -- call `find_violations` with `API_ROOT` / `ALLOWLIST_PATH` derived from `Path(__file__)` (mirror `generate_rbac_matrix.py`'s `SCRIPT_DIR`/`API_ROOT` pattern exactly). If violations exist, print each as `{router}:{line}: {code}` plus a one-line instruction ("add a reasoned entry to apps/api/rbac_bare_comparison_allowlist.json, or route this through require_role()/an imported core/roles.py constant instead"), then `sys.exit(1)`. If none, print a one-line confirmation and exit 0.

At the bottom, temporarily run `main()` against the current codebase with an allowlist path that doesn't exist yet (guard `load_allowlist` to treat a missing file as an empty allowlist for this dry run -- this is fine permanently, not just for the dry run, since a missing allowlist file should mean "nothing is allowlisted yet," not crash). Confirm the printed violation count and file/line list roughly matches this known inventory (**10 files, ~25 occurrences** -- NOT `safety.py:84`: `safety.py` imports `MANAGER_ROLES` directly from `core.roles` (`from core.roles import MANAGER_ROLES`), so its comparator is an `ast.Name` present in `imported_core_roles_names` for that file and this detector correctly classifies it as properly-sourced, not bare -- it will never appear in the violation output, and that is correct behavior, not a bug) before moving to Task 2 -- do not hand-write the allowlist from this list; Task 2 must capture the script's own `code` output verbatim:
`clean_sessions.py:66`, `guest_requests.py:213,300,334,375,382,444,476,493,590`, `late_checkout.py:61`, `logbook.py:124,176`, `lost_found.py:170,218,256`, `rooms.py:51,55,198`, `scheduling.py:278,311`, `tasks.py:142`, `work_orders.py:38,66,193`.
  </action>
  <verify>`cd apps/api && .venv\Scripts\python.exe scripts/check_bare_role_comparisons.py` (with no allowlist file present yet) prints one violation line per bare comparison found and exits 1; the file:line set matches the inventory above (allow +/-1 for edge cases like the guest_requests.py:382 ternary -- note any discrepancy and its cause in the Task 2 action before finalizing the allowlist).</verify>
  <done>find_bare_role_comparisons correctly walks whole router modules (not just route handlers, proven by rooms.py:51/55 and work_orders.py:38/66 appearing in the output) and imported_core_roles_names correctly distinguishes "imported from core/roles.py" from "any locally-known constant" (proven two ways: MESSAGE_ROLES/SUPERVISOR_ROLES/UNDO_ALL_ROLES-backed comparisons still appearing as bare since those are locally defined in the router file, not imported from core/roles.py; AND safety.py:84's MANAGER_ROLES-backed comparison correctly NOT appearing in the output, since safety.py imports MANAGER_ROLES from core.roles).</done>
