## Namespace collision check (already grep-verified during planning — do not skip this, it's real):
Neither `guestRequests` nor `lostFound` exists today as a reusable top-level object namespace. The SAME key names exist elsewhere but as plain strings under DIFFERENT parents (`tabs.guestRequests: "Requests"`, `home.gm.guestRequests: "Guest requests"`, `tabs.lostFound: "Lost & Found"`, `housekeeping...detailActions.lostFound: "Lost & Found"`). JSON allows the same key name under different parent objects with no conflict — creating new TOP-LEVEL `"guestRequests": {...}` and `"lostFound": {...}` objects is safe and won't collide. Grep both locale files for `"guestRequests":` / `"lostFound":` before you start to reconfirm this is still true (locale files may have changed since this research).

## Interpolation idiom (same as 09-00): `Room {x.room_number}` → `t("ns.key", { room: x.room_number })`, EN `"key": "Room {{room}}"`, ES `"key": "Habitación {{room}}"`.

## Plural idiom (i18next v23, CLDR `_one`/`_other` suffixes) — use this for the lost-found "N item(s) held" and sop "N procedure(s)" style counts instead of a raw ternary-in-JSX:
```
"itemsHeld_one": "{{count}} item held",
"itemsHeld_other": "{{count}} items held"
```
Called as `t("lostFound.itemsHeld", { count: items.length })` — i18next auto-selects the right suffix.

## Ternary-embedded string literals are NOT gate-flagged — do not touch them
Confirmed empirically: string literals living inside a JS ternary/conditional expression inside `{}` (e.g. `{filter === "all" ? "All Requests" : "New"}`) are NOT flagged by `i18next/no-literal-string` with `markupOnly:true` — only direct JSX text-node children and `aria-label`/`placeholder`/`title` attribute values are. Scope this plan strictly to the enumerated violations below — do not also wire ternary-embedded strings elsewhere in these 3 files (e.g. the `filter === "all" ? "All Requests" : ...` SectionLabel content in guest-requests/index.tsx, or `req.status.replace(...)` fallback labels) — that is out of scope per CONTEXT and would be scope creep beyond what the widened gate actually enforces.
</i18n_reference>
