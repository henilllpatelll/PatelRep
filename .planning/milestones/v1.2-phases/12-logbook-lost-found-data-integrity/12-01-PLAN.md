<objective>
Fix LOGBOOK-01: staff logbook entries written in the evening (hotel-local) silently disappear from the shift log because the entry's calendar day is computed in UTC, not the hotel's local timezone.

Purpose: An entry written at 8pm Central is 2am UTC the *next* day. Today the DB default `entry_date = CURRENT_DATE` (UTC) files it under tomorrow, and the list view filters `created_at` against naive UTC day boundaries — so it never shows under the day the housekeeper actually wrote it. This directly breaks the promise that the shift log proves what occurred.

Output: A logbook create path that stamps `entry_date` in hotel-local time, a list filter that queries the correctly-stored `entry_date` column, tests proving both boundary cases, and a backfill migration correcting existing mis-dated rows.
</objective>
