<objective>
Fix the housekeeping board so a room reflects who is actually assigned to it (from
`room_status.assigned_to`) even on a day with no matching `room_assignments` row —
instead of showing "Unassigned."

Root cause: `GET /housekeeping/board` (`apps/api/routers/housekeeping.py::get_housekeeping_board`)
spreads `**room` (which includes `room_status.assigned_to` from `select("*")`), but then
unconditionally overrides it:

```python
"assigned_to": assignment.get("assigned_to") if assignment else None,
```

When no `room_assignments` row exists for the requested date, `assigned_to` is forced to
`None`, discarding the live `room_status.assigned_to` mirror. The frontend
(`RoomStatusBoard.tsx`) resolves the housekeeper name from `assigned_to` via
`hkNameById[...]` and `AssignmentSidebar.tsx` counts `!room.assigned_to` as unassigned, so
the room renders as "Unassigned" even though a housekeeper is actually on it.

The fix is a one-line fallback to `room.get("assigned_to")`.

DELIBERATE BEHAVIOR REVERSAL — READ BEFORE EDITING:
An existing test, `test_board_uses_selected_date_assignments_not_stale_room_status`
(apps/api/tests/smoke/test_housekeeping_assignments.py), encodes the OLD intent: for a room
whose only `room_assignments` row is dated yesterday (`room_unassigned_today`,
room_status.assigned_to = hk_yesterday), it asserts
`by_room[room_unassigned_today]["assigned_to"] is None`. Phase 14's ROOMSTATUS-01 explicitly
overturns this — room_status.assigned_to is now authoritative when there is no today row.
`room_status` has no per-assignment timestamp, so "current" and "stale-from-yesterday"
mirrors are indistinguishable in code; the requirement resolves the ambiguity in favor of
always surfacing room_status.assigned_to. This plan updates exactly that one assertion (and
only that one) and documents why. It does NOT invent an assignment where none exists — the
`assignment_id`, `assignment_date`, `assignment_shift_id`, and `clean_type` fields stay
`None` for such a room; only `assigned_to` is surfaced.

Purpose: Housekeeping supervisors see the real assignee on the board, not a false "Unassigned."
Output: A one-line backend fallback + regression tests for all 3 success criteria + a
confirmed, deliberate reversal of the prior "not stale" behavior.
</objective>
