## Milestone Summary

**Key Decisions:**

- One evidence platform reused across training/safety/maintenance/SOP/compliance rather than parallel mechanisms per domain (Phase 2 → reused through 3-4).
- Five vertical deliverables built in dependency order (applicability → documents → evidence → competency → exceptions).
- Phase 6 reframed as audit-first hardening, not greenfield, once discuss-phase found the "backlog" was already shipped and live — bugs fixed in-phase rather than building on an unverified foundation.
- Opera PMS pilot-gating via a single `tenants.opera_pilot_enabled` boolean (YAGNI over a richer `pilot_features` table — only one integration needed gating).
- AI copilot credit billing derives cost from real token usage (`MODEL_RATES` × `DOLLARS_PER_CREDIT`) with `CREDIT_COSTS` retained only as a revenue floor.

**Issues Resolved:**

- Migration-079 fix: `SECURITY DEFINER` RPCs executable by `anon`/`authenticated` — revoked, granted `service_role` only (Phase 2).
- bug-449: `.maybe_single()` None-handling gap (Phase 3).
- Phase 6: flat-cost credit billing, SOP double-logging (plus a second unaudited billing gap in `/sop/query`), Opera webhook signature keyed on the wrong secret, a misleading Opera-settings UI form shown alongside a 403 error.
- **Milestone cross-phase audit (post-Phase-6):** AI-copilot guest-request creation silently bypassed the entire SLA/escalation/audit contract Phase 5 built — found by the v1.0 audit's cross-phase integration check (an intra-phase audit structurally cannot see this class of gap) and fixed same-session, not deferred.
- Zombie dev-server processes + a missing `apscheduler` dependency were silently serving 3-day-stale code during Phase 6's first live-walkthrough attempt — caught before being trusted as evidence, environment fixed, walkthrough redone against verified-fresh code.

**Issues Deferred:**

- Live Twilio SMS send/inbound/status-callback paths unexercised in production (no Twilio credentials locally — D-01, Phase 5, accepted).
- Live OHIP sandbox round-trip and real LLM provider output unexercised locally (no credentials — Phase 6, accepted, consistent with Phase 5's precedent).
- Oracle OHIP's exact webhook signing scheme (header/algorithm) unverified against a live sandbox — the fix guarantees correct secret sourcing and fail-closed behavior regardless (Phase 6, T-06-17, accepted).

**Technical Debt Incurred:**

- Phase 2 and Phase 3 predate the VERIFICATION.md/SUMMARY-frontmatter traceability convention — REQ-201..207 (Phase 2) and Phase 3's work are verified via STATE.md narrative + direct codebase inspection rather than the standard artifact.
- `guest_requests.py` uses inline `current_user.role` checks instead of the `require_role()` dependency pattern used elsewhere (functionally equivalent, cosmetic inconsistency — found during the v1.0 integration audit).
- CLAUDE.md's documented cron mechanism (GitHub Actions + `X-Cron-Secret`) is stale — the project now runs crons in-process via APScheduler (`apps/api/core/scheduler.py`). Code is correct; the top-level doc needs updating in the next milestone.
- `opera_credentials.webhook_secret` is schema-provisioned but not yet written by `opera_connect` — will need population when a real Opera pilot hotel is enrolled (flagged in 06-RESEARCH.md, out of Phase 6's scope).
