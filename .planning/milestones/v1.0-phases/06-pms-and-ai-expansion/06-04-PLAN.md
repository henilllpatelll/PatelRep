<objective>
Fix the Opera webhook security defect research found and extend the D-03 pilot gate to the push (webhook) path, tests-first.

1. **Webhook signature verifies the wrong secret (D-05, real security bug).** `routers/webhooks.py::_verify_opera_signature()` derives its HMAC key from `CRON_SECRET + hotel_id` — an internal secret Oracle never knows. As implemented it can only validate payloads forged by someone who also knows `CRON_SECRET`; it can never validate an authentic Oracle-signed payload. The schema already has the intended per-hotel `opera_credentials.webhook_secret` column (migration 002, currently unused). Fix: source the HMAC key from `opera_credentials.webhook_secret`, mirroring the CORRECT `_verify_twilio_signature` pattern in the same file.
2. **Pilot gate on the webhook path (D-03).** The webhook dispatcher (`opera_webhook`) cannot return 403 (Oracle isn't redirectable). It must silently no-op for non-pilot hotels, mirroring the EXISTING "hotel not found or not connected" silent-ignore shape.
3. **Full webhook coverage (D-06).** New `test_opera_webhooks.py`: signature (correct vs wrong secret), per-handler dispatch (room_status + history writes, tenant-scoped), pilot no-op, unknown-event/unknown-hotel no-ops.

Depends on 06-02 (needs migration 085's `opera_pilot_enabled` column + the pilot-gate concept established there).

**Open Question flagged for the executor (06-RESEARCH Open Question 1 / Assumption A1):** This session could NOT verify Oracle OHIP's actual Business Events webhook signing scheme (header name, hash algo, canonicalization). The `webhook_secret` column is also not currently written by `opera_connect`. Scope the fix to the verifiable, correct-by-construction goal — "verification uses a per-hotel secret from opera_credentials.webhook_secret, structurally identical to the working Twilio check" — and DOCUMENT (in the SUMMARY + a code comment) that matching Oracle's exact real-world header/algorithm requires a live OHIP sandbox the project lacks. Do NOT "fix" the check by making it always pass in production.
</objective>
