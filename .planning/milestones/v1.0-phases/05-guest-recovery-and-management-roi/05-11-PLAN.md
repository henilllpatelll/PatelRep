## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → SLA rule writes | A tenant-wide configuration change affecting the promised response time on every future guest request |
| staff browser → accessible-room feature writes | Operational data that staff will rely on when directing a guest with an accessibility need |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-11-01 | Elevation of Privilege | A non-manager creating or deleting SLA rules | mitigate | The page hides write controls behind `canManage = isGM \|\| role === 'housekeeping_supervisor'`, the nav entry carries the same `roles` array, and the API returns 403 for anyone else — three layers, with the API authoritative |
| T-05-11-02 | Elevation of Privilege | A non-manager editing accessible-room features | mitigate | The add/edit form renders only for `{gm, housekeeping_supervisor, engineer}`, matching the API's existing `PUT` gate exactly; the read table stays visible to any settings viewer |
| T-05-11-03 | Tampering | An SLA rule that silently disables the response clock | mitigate | The form enforces `min=1 max=10080` and blocks the all-wildcard case; the API re-validates both with Pydantic bounds and a 422 |
| T-05-11-04 | Repudiation | A duplicate rule silently shadowing another | mitigate | The API returns 409 with a specific message and the page surfaces the API `detail` verbatim rather than a generic "save failed" |
| T-05-11-05 | Information Disclosure | Cross-tenant SLA rules or room features | mitigate | Both endpoints are tenant-scoped server-side; the client sends no tenant identifier |
| T-05-11-06 | Tampering | Stale accessibility status misdirecting a guest with an access need | mitigate | The API stamps `last_verified_at` on every upsert and the table renders it, so a manager can see when a feature's status was last confirmed |
| T-05-11-07 | Denial of Service | Duplicate rooms fetch on every tab switch | mitigate | The accessibility tab reuses the page's existing `allRooms` memo; an acceptance criterion asserts no second `roomsApi` call was introduced |
</threat_model>
