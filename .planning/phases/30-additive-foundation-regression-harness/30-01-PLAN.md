<objective>
Stand up the Playwright pixel-diff regression harness that captures pre-redesign baseline screenshots of the 3 excluded Room Board surfaces (RoomStatusBoard, RoomDetailDrawer, EngineeringRoomBoard) in light and dark mode for two real roles, and re-checks them for zero drift. This is FOUND-03 — the deepest safety guarantee of the whole v2.0 milestone; per the requirement it must be captured BEFORE any token/primitive work begins. Runs in Wave 1 so the baseline reflects the untouched tree.

Purpose: Every later phase (30-04 tokens onward, Phases 31-36) re-runs this diff to prove the excluded boards never visually drift. It must be trustworthy enough to leave wired into CI on every PR — which means an unchanged tree must render BYTE-IDENTICALLY, so the diff can distinguish "a frozen primitive drifted" from ordinary data change. A live production board (rooms getting cleaned, statuses flipping) can never satisfy `maxDiffPixelRatio: 0`; masking only covers chrome, not which rooms exist or their status colors. Therefore this plan pins a deterministic, never-operated fixture data source — AND seeds that fixture in cron-inert states, because the production in-process scheduler (APScheduler in `apps/api/core/scheduler.py`) sweeps ALL tenants every 30 minutes and some jobs write fields the boards render (see Task 1). "No human operates it" is necessary but not sufficient; "no cron can mutate it" is what actually guarantees determinism.
Output: A cron-inert seed script + committed baseline snapshot set + a regression config/spec any phase can run.
</objective>

  - Deterministic ordering (stable room numbers/floors) so layout never reshuffles.

- **Work orders — cron-inert (confirmed against source):** upsert a FIXED set of work orders so EngineeringRoomBoard renders stable content, seeded so `escalations.check` (`internal.py` ~lines 501-543) cannot bump `escalation_level`/`status`. That query targets WOs with `status IN (open, in_progress)` AND `assigned_to IS NOT NULL` AND `due_at < now` AND `escalation_level < 3`. Defeat it by setting, for every fixture WO: `due_at` NULL or far-future (e.g. year 2099) so `due_at < now` is never true, AND `escalation_level = 0`. This keeps WOs rendering as active work on the board while being permanently inert. (Alternative if the board's inert render is acceptable: `status='completed'`, which also drops out of the filter — note whichever is chosen in the SUMMARY.)

- **Any fixture tasks (if seeded):** the task escalation branch (`internal.py` ~lines 546-588) requires `priority='urgent'` AND `due_at < now`; seed fixture tasks non-urgent OR with future/NULL `due_at` so they are inert too.
