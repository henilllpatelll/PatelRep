```sql
ALTER TABLE public.tenants
  ADD COLUMN IF NOT EXISTS web_redesign_sections TEXT[] NOT NULL DEFAULT '{}';
COMMENT ON COLUMN public.tenants.web_redesign_sections IS
  'Per-section v2.0 redesign rollout gate. Each element is a section key (e.g. "shell","tasks","engineering") whose redesigned UI is live for this tenant. Empty = all old UI. DB/admin-flipped, no GM toggle. Removed in the v2.0 cleanup once all tenants migrated (v2.0 FOUND-06).';
-- ROLLBACK: ALTER TABLE public.tenants DROP COLUMN web_redesign_sections;
```
DECISION (per RESEARCH.md open question #2): use a `text[]` of section keys, NOT the boolean `web_redesign_enabled` that CONTEXT.md's naming example suggested. Rationale to record in SUMMARY: the same CONTEXT decision mandates per-section granularity and explicitly warns against a single blanket switch — an array delivers that granularity and matches the `front_desk_modules` precedent (per-tenant, DB-flipped). No GM toggle, no RLS change (it is a read-only field on a row the tenant already reads via /auth/me).

In `apps/api/routers/auth.py`, add `web_redesign_sections` to the `tenants` select list in `get_me` (currently `id, name, timezone, room_count, logo_url, front_desk_modules` at line ~19). No new endpoint, no gating logic in the API — the flag is a plain data field the web reads (keeps flag checks out of API business logic per the lifecycle constraint).
