  <action>
Create `apps/web/scripts/check-contrast.mjs` — a ~50-line pure-Node WCAG computation (no axe/Lighthouse dependency; those belong to the final-QA rendered sweep, not this token-matrix gate):
- Parse hex token values from `globals.css` `:root` and `.theme-dark`.
- Define TWO pairing sets, kept explicitly separate:
  1. **ENFORCED — NEW-token pairings only** (FOUND-04 scope): foreground-on-background combos introduced by the NEW tokens from 30-04 that later phases will render — e.g. `--brand-ink` on `--brand`, `--ink`/`--ink-2` on `--surface-raised` and `--surface-overlay`, and any other new-token pairing. These are checked and the gate EXITS 1 if any falls below threshold.
  2. **REPORT-ONLY — frozen room-status pairings** (e.g. each room-status text token on its `-soft` background: dirty/clean/inspected/in_progress/pickup/ooo). These tokens are VALUE-frozen with NO allowlist — the gate must NEVER fail on them and must NEVER propose tuning them. Compute and print their ratios for the record ONLY (visibility for downstream awareness), clearly labeled "report-only (frozen room-status — not enforceable)".
- Do NOT invent pairings that never render; ground them in token roles.
- Compute WCAG relative luminance + contrast ratio for each pairing in BOTH light and dark. Thresholds: >=4.5:1 body text, >=3:1 large text / UI. Handle `color-mix(...)` tokens (e.g. `--focus-ring`) by resolving against a stated base or skipping non-solid tokens with a documented note.
- Exit 1 listing any ENFORCED pair below threshold with its ratio; exit 0 otherwise. Report-only pairs never affect the exit code.

Write both tables (enforced + report-only) to `CONTRAST.md` (per PITFALLS Pitfall 3). If an ENFORCED (new-token) dark value fails, adjust that NEW dark token value in `globals.css` (a new additive token, safe to tune — not a pre-existing frozen value) until AA passes, and note the adjustment. If a REPORT-ONLY room-status pair is below AA, record it and do NOT change anything (the value is frozen by hard constraint).
  </action>
  <verify>cd apps/web && node scripts/check-contrast.mjs exits 0 with all ENFORCED new-token pairings >= threshold in both modes; report-only room-status ratios are printed but never affect exit code (verify by confirming exit 0 even if a room-status pair is below AA); CONTRAST.md contains both tables</verify>
  <done>Every NEW-token pairing meets WCAG AA in light AND dark (gate enforces these); frozen room-status pairings are recorded report-only and never fail/tune; ratios in CONTRAST.md; any failing new-token dark value was tuned additively to pass</done>
