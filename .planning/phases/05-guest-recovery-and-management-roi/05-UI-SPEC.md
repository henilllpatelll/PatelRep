# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Reuse phase, not greenfield.** This project has a mature, hand-rolled design system in production since Phase 1 (`apps/web/app/globals.css`, `apps/web/tailwind.config.ts`, `apps/web/components/ui/*`). No shadcn, no component-library dependency. Every value below is extracted from existing code (`GuestRequestsPage.tsx`, `GuestRequestDrawer.tsx`, `settings/inspections/page.tsx`, `settings/rooms/page.tsx`, `lost-found/page.tsx`, `reports/page.tsx`), not invented. New Phase 5 surfaces must match these values exactly — do not introduce new tokens, new component patterns, or a new visual language.

## Spacing Scale

Declared values (must be multiples of 4) — already in force throughout the codebase via Tailwind defaults + `tailwind.config.ts` (`spacing['13'] = 52px` is the only custom token; everything else is stock Tailwind 4px-grid):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (`gap-1`, `gap-1.5`) |
| sm | 8px | Compact spacing inside cards/pills (`gap-2`, `p-2`) |
| md | 16px | Default element spacing, card padding (`p-4`, `px-4 py-3`) |
| lg | 24px | Section padding, page-level `space-y-6` |
| xl | 32px | Layout gaps between major regions |
| 2xl | 48px | Major section breaks (empty-state vertical padding `py-12`/`py-16`) |
| 3xl | 64px | Not used at Phase 5 scope — reserve for full-page empty states only |

Exceptions:
- Kanban card touch buttons use `min-h-[30px]` (below the 36px Button default) — an established exception for dense 3-column kanban card actions (`GuestRequestsPage.tsx`); do not introduce further sub-36px targets elsewhere.
- Global rule (`globals.css`): all buttons/inputs get `min-height: 44px` under `(max-width: 640px), (pointer: coarse)` — mobile/touch always overrides desktop density. New Phase 5 controls (message reply box send button, disposition-approval buttons, SLA-policy form) must not opt out of this.

## Typography

Established system (from `layout.tsx` + observed usage). Declaring the **2 core weights** and **4 font sizes** for new Phase 5 elements, plus 1 inherited system-wide weight exception:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 11px, uppercase, `tracking-[0.08em]`–`[0.1em]` | 600 (semibold) | 1.3 (matches `SectionLabel`/drawer section headers) |
| Heading (page/drawer h1, h2) | 20px (settings h2 `text-base`→18-20px range) | 600 (semibold) | 1.2 |
| Display (KPI/hero numbers only) | 32px, `font-display` (Instrument Serif) | 400 (regular — the serif has no other weight) | 1.1 |

**Legacy exception — do not replicate:** `GuestRequestsPage.tsx`'s existing kanban page `<h1>` uses 22px, a pre-existing value that predates this spec. It is left as-is (no regression work in scope), but every **new** Phase 5 heading — the message thread panel inside `GuestRequestDrawer.tsx`, `settings/guest-requests/page.tsx`, the `settings/rooms/page.tsx` accessibility tab, and `management-roi/page.tsx` — must use **20px**, not 22px. Do not carry the 22px value into any new surface; this keeps the contract at exactly 4 distinct sizes (11 / 14 / 20 / 32).

**Weight exception (inherited, do not extend further):** `font-medium` (500) already appears codebase-wide on buttons (`Button.tsx`), tabs, pills, and table headers. Phase 5 new components should reuse existing `Button`/`Pill`/tab components as-is (which already carry 500) rather than hand-rolling new 500-weight elements — this keeps the "2 new weights" rule honest for anything genuinely new while not requiring a rewrite of shared primitives.

Numeric/room-number/ID values use `font-mono` (IBM Plex Mono) — e.g. room numbers in kanban cards and drawer header (`font-mono text-[20px] font-bold`, `font-mono text-[26px] font-bold`). Any new Phase 5 numeric identifier (e.g. lost-found tag/bag ID, SLA minutes value) must use `font-mono`, matching this precedent.

## Color

60/30/10 split already encoded in `globals.css` CSS variables — reuse the variables, never hardcode hex:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--paper` `#f7f4ee` (page bg) / `--surface` `#ffffff` (card/panel bg) | Page background, drawer/modal background, card fills |
| Secondary (30%) | `--surface-2` `#fbf9f4`, `--surface-3` `#f1ede4`, `--line` `#e6dfd1` | Kanban column bodies, table header rows, borders, skeleton loaders |
| Accent (10%) | `--accent` `#b8431c` (terracotta) | **Reserved for:** primary CTA buttons only (`Send Reply`, `New SLA Rule`, `Approve Disposition`, `Log Found Item`, `Import Rooms`), active tab underline+text, focus rings (`focus:ring-[var(--accent-soft)]`), the accent-tone `Pill`. Never use accent for status/semantic meaning (SLA state, delivery state, disposition state) — those use the dedicated semantic tokens below. |
| Destructive | `--alert` `#a6263c` (rose) | Destructive/irreversible actions only: delete SLA rule, delete lost-found item, SLA-breach indicator text, `engineer`-role RBAC-denied states |

**Established semantic tokens (not new — reuse verbatim) and their Phase 5 mapping:**

| Token | Existing meaning | Phase 5 usage |
|---|---|---|
| `--ready` (teal) | success/inspected/verified | Guest request `verified` status, "SLA Met" %, delivered SMS, ROI "Time Saved" theme section icon color |
| `--caution` (amber) | pickup/warning | SLA-approaching, `disposition_due` flag pill, queued SMS delivery status, ROI "Response" theme section icon color |
| `--info` (blue) | clean/neutral-progress | Sent (not yet delivered) SMS status, ROI "Quality" theme section icon color |
| `--alert` (rose) | dirty/breach/destructive | SLA breach, failed SMS delivery, opted-out contact indicator, disposition-discard destructive confirm |
| `--blocked` (gray) | out-of-order/inert | Opted-out guest (blocks further sends), cancelled guest request, discarded lost-found item |
| `--progress` (purple) | in-progress | Guest request mid-lifecycle states (dispatched/arrived/guest_contacted) if a distinct tone is needed beyond the existing 3-column kanban header colors |
| `--ai` (indigo) | AI-specific | Do not use in Phase 5 — no AI-generated content in this phase's new surfaces |

**Management ROI dashboard (D-06) 4-theme mapping** (icon/accent color per section only — sections are plain white `Stat` cards on `--paper` background, not color-filled blocks, matching the existing `reports/page.tsx` KPI-grid convention):
- **Time Saved** → `--ready` (teal icon/value accent)
- **Quality** → `--info` (blue icon/value accent)
- **Response** → `--caution` (amber icon/value accent)
- **Revenue Protected** → `--accent` (terracotta icon/value accent — the one place per-section accent color is acceptable, since it is a value/label accent color on a `Stat` card, not a CTA)

Accent reserved for: primary CTA buttons (listed above), active tab indicator, focus rings, and the Revenue Protected `Stat` card's value color on the Management ROI dashboard only. Never for backgrounds, borders on non-interactive containers, or default body text.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — message reply | "Send Reply" (Button `variant="primary"`, `Send` icon — matches existing "Save Note" pattern in `GuestRequestDrawer.tsx`) |
| Primary CTA — SLA policy settings | "New SLA Rule" (mirrors existing "New Template" on `settings/inspections`) |
| Primary CTA — disposition approval | "Approve Disposition" |
| Primary CTA — lost & found (existing, unchanged) | "Log Found Item" |
| Empty state — message thread | Heading: "No messages yet" · Body: "Outbound texts to the guest and their replies will appear here in order." |
| Empty state — SLA policies list | Heading: "No SLA rules yet" · Body: "Create a rule to override the default 240-minute response time by category, priority, and guest impact." |
| Empty state — disposition-due filter | Heading: "Nothing due for disposition" · Body: "Items flagged after their 90-day retention period passes will show up here for manager review." |
| Empty state — Management ROI (no data yet) | Heading: "Not enough data yet" · Body: "Metrics populate as guest requests, work orders, and inspections are recorded over time." |
| Error state — message send failure | "Message failed to send. The guest may have opted out, or the number may be invalid. Check the thread below for delivery status." |
| Error state — generic fetch failure (existing pattern) | "Failed to load {noun}. Please try again." (reuse verbatim per `reports/page.tsx`'s `isError` blocks) |
| Destructive confirmation — delete SLA rule | "Delete this rule?" · "Guest requests in this category will fall back to the default SLA once removed." |
| Destructive confirmation — disposition (donate/discard) | "Approve disposition: mark as {donated / discarded}" · "This creates a permanent, append-only record and cannot be undone." (matches the codebase's append-only convention — same tone as `DeleteConfirmDialog`'s default "This action cannot be undone.") |
| Destructive confirmation — opted-out contact attempt | Not a confirm dialog — inline disabled state on the reply box: "This guest has opted out of SMS. Replies are disabled." |
