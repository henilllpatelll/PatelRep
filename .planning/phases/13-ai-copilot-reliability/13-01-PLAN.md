<objective>
Fix the real defect behind AI-01: `AssignmentSidebar.tsx::handleAiAutoAssign` reads `result.data?.assignments_created ?? result.data?.count` — two keys that do not exist anywhere in the actual `/housekeeping/ai-suggest-assignments` response (`apps/api/routers/housekeeping.py:974-1182`, which is a pure rule-based, read-only suggestion endpoint returning `{"data": {"suggestions": [...], "date", "shift_id", "message"}}`). Today this means `count` is always `null`, so a generic "success" toast fires and three query caches are invalidated on every 200 response even when the board has zero rooms needing work — a fake-success bug, not the "silent 422" the requirement text describes (client.ts's shared error parser already surfaces real HTTP errors correctly).

Purpose: A supervisor must be able to trust what the AI assignment button tells them — an accurate suggestion summary, an honest "nothing to do" message, or a real visible error — never a misleading success.
Output: `AssignmentSidebar.tsx` reads the actual response shape and presents an honest, suggestion-only UX; locale copy no longer implies a persisted action; a new backend regression test locks the response contract this fix depends on.
</objective>
