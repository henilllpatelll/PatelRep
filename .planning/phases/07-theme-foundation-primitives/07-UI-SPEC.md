# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 7 ships zero visible change to any existing screen (Success Criterion 5). There is no "screens" section — instead this contract specifies the exact visual/interaction spec for the **new primitives themselves**: `useTheme()`/`ThemeProvider`, `ToastProvider`/`useToast()`, `Button`/`IconButton`, `Card`, `EmptyState`/`StateBlock`, and `StatusBadge`. All values are sourced from the existing "Evening Lobby" token system (`apps/mobile/components/shared/tokens.ts`) — nothing here invents a new palette, spacing scale, or icon set. Dark mode is defined in tokens but **not visually active** this phase (light-only-active per THEME-01); the color values below are the light-theme values that must render identically before and after this phase ships.

## Spacing Scale

The project's existing scale (`R`/`S` in `tokens.ts`) is the canonical scale for this phase — it predates this milestone, is used by 46+ files, and is explicitly protected by `ARCHITECTURE.md`'s Anti-Pattern 1 ("do not relocate/rewrite the token file"). It is **not** a strict 4px-multiple scale; that is a documented, intentional exception, not an oversight.

| Token | Value | Usage |
|-------|-------|-------|
| `R.sm` | 8px | Small radius (chips, small tiles) |
| `R.md` | 12px | **Default primitive radius** — Button, IconButton, StatusBadge container, Toast |
| `R.lg` | 16px | **Card radius** (matches `RoomQueueCard`'s existing shell) |
| `R.xl` | 20px | Large surfaces (AI cards; not used by Phase 7 primitives) |
| `S.page` | 18px | Screen-edge padding (screen-owned, not a primitive concern this phase) |
| `S.card` | 16px | **Card internal padding** (all sides, when Card has no status rail) |
| `S.cardGap` | 15px | Gap between stacked cards (screen-owned) |
| `S.sectionGap` | 22px | Section-level spacing (screen-owned) |

**New primitive-specific spacing (not in `tokens.ts` — additive, small, and consistent with existing patterns like `heroButton`/`claimBtn`/`segment`; every value below is a 4px multiple):**

| Value | Usage |
|-------|-------|
| 4px | Icon-to-label gap inside StatusBadge tightest case |
| 8px | StatusBadge horizontal padding; icon-to-text gap (Button icon+label) |
| 12px | Button `sm` horizontal padding; Toast vertical padding; Toast icon-to-text gap |
| 16px | Button `md` horizontal padding; Toast horizontal padding |
| 24px | Button `lg` horizontal padding |
| 32px | EmptyState/StateBlock outer padding (empty/error variants) |

Note: an earlier draft used 6px/10px/14px for the icon-to-text and Toast padding/gap values above; these were snapped to the nearest 4px multiple (6→8, 10→12, 14→16) so every new primitive-specific value sits on the 4px grid — the matching Toast container spec below uses the snapped values.

Exceptions: the `S`/`R` scale itself is the phase's declared exception to the generic 4px-multiple rule — see rationale above. No further exceptions.

## Typography

Scale declared for **Phase 7 primitives only** (Button, Card, EmptyState/StateBlock, StatusBadge, Toast). Existing screens are untouched this phase and keep their current type scale.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 11px | 800 (extrabold) | 14px (~1.27) — matches existing `statusPillText`/`pillText` convention |
| Body | 14px | 600 (semibold) | 21px (1.5) — EmptyState/StateBlock body message, Card default body text |
| Button label | 15px | 600 (semibold) | 18px (1.2) — Button `md` size (see per-size table below) |
| Heading | 16px | 600 (semibold) | 19px (1.2) — EmptyState title |

Two weights only: **600** (semibold — body, headings, button labels) and **800** (extrabold — StatusBadge/pill-style uppercase labels). This mirrors the codebase's existing dominant pattern (`statusPillText`/`chipText`/`badgeText` all use 700–800; body copy uses 500–600) rounded to exactly two weights for new primitives.

Text casing: Label role (StatusBadge) is **uppercase** with `letterSpacing: 0.3`, matching `statusPillText`. Body/Heading/Button label are normal case.

`Display` role: not used by any Phase 7 primitive — out of scope (existing 28px monospace room-number style stays screen-owned in `evening.tsx`, untouched).

## Theme Shell Contract (THEME-01)

- `useTheme()` (in `lib/theme/useTheme.ts`) returns `getThemeTokens(mode)` from the existing `tokens.ts` — same object shape as `lightTheme`/`darkTheme` today. No new keys invented.
- `mode` this phase is **always `"light"`**, regardless of `useColorScheme()` result — the hook reads the OS scheme for future wiring (Phase 10) but the resolved theme is pinned to light so zero screen renders differently. Do not let `useColorScheme()` flip the active palette in Phase 7.
- Provider `value` MUST be memoized (`useMemo`) per `PITFALLS.md` Pitfall 5 — a fresh object per render risks re-rendering the whole tree and disturbing the `NetInfo`/auth effects in `app/_layout.tsx`.
- `<ThemeProvider>` mounts in `app/_layout.tsx`, wrapping everything including `(auth)` — so login is theme-ready before Phase 10 needs it.
- Primitives (`components/ui/*`) consume colors **only** via `useTheme()` — never import `lightTheme`/`darkTheme`/`C` directly. This is the enforceable boundary the checker/executor should verify.
- Because `mode` is pinned to light, every color value a primitive resolves via `useTheme()` in Phase 7 MUST be byte-identical to the corresponding `lightTheme`/`C.*` value already in use — this is the mechanism that guarantees Success Criterion 5 ("zero visual change").

## Primitive Component Contracts

### Button / IconButton (UI-01)

**Button — variants** (D-06):

| Variant | Default bg | Default text/icon | Pressed bg | Disabled |
|---|---|---|---|---|
| `primary` | `#4F7A5A` (`C.accent`) | `#FFFFFF` | `#2F5D50` (`C.primary`, i.e. darker shade — swap fill on press) | 40% opacity, no press feedback |
| `secondary` | `#FFFDFC` (`C.surface`), border 1px `#E4D6C4` (`C.line`) | `#2C2621` (`C.ink`) | bg → `#F0EBE1` (`C.surface3`) | 40% opacity |
| `ghost` | transparent, no border | `#4F7A5A` (`C.accent`) | bg → `#E0EBE1` (`C.accentSoft`) | 40% opacity |
| `destructive` | `#A9363F` (`C.alert`) | `#FFFFFF` | bg → `#8A2C34` (darken ~10%) | 40% opacity |

**Button — sizes** (D-07). All three sizes meet the ≥44pt/48dp touch-target floor directly via `minHeight` (no `hitSlop` workaround needed):

| Size | minHeight | Horizontal padding | Font size | Icon size | Radius |
|---|---|---|---|---|---|
| `sm` | 44 | 12 | 14px / weight 600 | 14 | `R.md` (12) |
| `md` | 48 | 16 | 15px / weight 600 | 16 | `R.md` (12) |
| `lg` | 56 | 24 | 16px / weight 600 | 18 | `R.md` (12) |

**Loading state** (D-07): the label `Text` renders with `opacity: 0` (preserving its intrinsic layout width/height) while an `ActivityIndicator size="small"` is absolutely positioned centered over it — this is the mechanism that satisfies "no layout shift, button keeps its size/position." Spinner color = the variant's foreground color (`#FFFFFF` for primary/destructive, `#4F7A5A` for secondary/ghost). `disabled` is implied true while `loading`.

**Pressed feedback:** implement with `Pressable`; opacity/background swap as above, no separate `activeOpacity` prop needed (matches codebase's `0.84–0.85` press-feedback convention already used by `HeroButton`/`WorkOrderCard`'s claim button, translated to a `Pressable` state-based style).

**Style merge order** (Pitfall 6, locked contract for all 4 new primitives): `style={[styles.base, variantStyle, sizeStyle, props.style]}` — base structural styles first, then variant, then size, caller override always last.

**HeroButton** (`mobileHandoff.tsx`) is explicitly untouched — separate component, no call sites change (D-05).

**IconButton** (D-08): kept structurally as-is (`icon`, `tone`, `size = 36` default props unchanged). This phase only re-wires its internal color resolution from the static `C` import to `useTheme()`. **Known gap, explicitly accepted:** the existing default `size={36}` is below the 44pt/48dp floor UI-01 requires for *new* touch targets. Do not silently "fix" this in Phase 7 (D-08 forbids adding a new size surface). Any Phase 8+ screen that adopts `IconButton` in a context requiring a guaranteed touch target **must** pass `size={44}` or greater explicitly — flag this constraint to the Phase 8 planner. **Accessibility requirement (structural surface stays frozen, but this is a required prop contract, not a new size/variant):** because `IconButton` is icon-only with no visible text, every call site MUST pass an `accessibilityLabel` prop describing the action — `IconButton` renders no fallback/default label.

### EmptyState / StateBlock (UI-03)

Single component, one `status` prop drives rendering: `"loading" | "empty" | "error"`. Children render only when data is present (caller decides that condition; `StateBlock` renders its own UI for the other three states).

| State | Rendering |
|---|---|
| `loading` | Centered `ActivityIndicator size="large"` color `#4F7A5A` (`C.accent`), vertical padding `S.sectionGap` (22) top/bottom. Same visual pattern the 38 files already hand-roll today — centralized, not redesigned (D-13). No skeleton loader (explicitly deferred). |
| `empty` | Centered column: `Ionicons` icon (caller-provided name, size 40, color `#807A70` i.e. `C.ink3`/`textMuted`) → 8px gap → title (Heading role: 16px/600, color `C.ink`) → 4px gap → body message (Body role: 14px/600, color `C.ink3`). Outer padding 32 all sides. |
| `error` | Same layout as `empty`, icon defaults to `alert-circle-outline`, icon color `#A9363F` (`C.alert`), message color `C.ink2`. If `onRetry` prop is provided, render a `Button` (`variant="secondary"`, `size="md"`) below the message with an 16px top gap; if omitted, no button renders (D-14 — no caller is forced to wire retry). |

Every string (title, message, retry-button label) is a **required caller prop** — `StateBlock` renders no hardcoded English defaults, satisfying the i18n floor contract and Pitfall 4.

### StatusBadge (UI-04)

Single component, `statusKey` prop selects the color+icon+label triplet. **Always** renders icon + label + color together — no compact/icon-only mode (D-11), and reads colors via `useTheme()` → `statusTokens`/`darkStatusTokens` from day one (D-12), even though only light mode is reachable this phase.

**Container:** pill shape — `borderRadius: 999`, `borderWidth: 1`, `paddingHorizontal: 8`, `paddingVertical: 4`, `minHeight: 22` (informational label, not a touchable — the 44pt floor does not apply), `flexDirection: row`, `gap: 4`, icon size 12, label = Label role (11px/800, uppercase, `letterSpacing: 0.3`).

**Icon set — formalized from `WorkOrderCard.tsx`'s existing convention, extended to cover room-status states per D-10 (both families share `statusTokens`/`darkStatusTokens`):**

| Status family | `statusKey` | Icon (Ionicons) | bg / fg / border |
|---|---|---|---|
| Room status | `ready` (INSPECTED) | `checkmark-circle` | `readySoft` / `ready` / `readyLine` |
| Room status | `clean` (CLEAN, awaiting inspection) | `checkmark-done-outline` | `cleanSoft` / `clean` / `cleanLine` |
| Room status | `dirty` (DIRTY, vacant) | `brush-outline` | `dirtySoft` / `dirty` / `dirtyLine` |
| Room status | `occupied` (OCCUPIED, guest present) | `person-outline` | `dirtySoft` / `occupied` / `dirtyLine` (shares dirty hue per existing `STATUS_META`) |
| Room status | `pickup` | `alert-circle-outline` | `pickupSoft` / `pickup` / `pickupLine` |
| Room status | `outOfOrder` (OOO/OUT_OF_ORDER/OUT_OF_SERVICE) | `close-circle-outline` | `outOfOrderSoft` / `outOfOrder` / `outOfOrderLine` |
| Work order | `emergency` | `warning` | `alertSoft` / `alert` / `alertLine` (direct lift from `WorkOrderCard`) |

### ToastProvider / useToast() (THEME-02)

**Placement (D-01):** `<ToastProvider>` + its viewport mount in `app/(app)/_layout.tsx` (authed surfaces only — matches `OfflineBanner`'s existing mount point). The toast viewport renders **below** `OfflineBanner` in the same vertical stack, never overlapping it:
- If `OfflineBanner` is visible (device offline), the toast's top edge sits flush against the banner's bottom edge (0 gap) — measure the banner's rendered height (`onLayout`) rather than hardcoding a magic number, since `OfflineBanner` is inline/conditional, not absolutely positioned.
- If `OfflineBanner` is hidden, the toast's top edge sits at `useSafeAreaInsets().top` (already-installed `react-native-safe-area-context`) with 0 additional margin — flush below the status bar/notch, matching the app's existing safe-area convention.
- Toast itself IS absolutely positioned (`position: "absolute"`, full width minus `marginHorizontal: 12`) so it floats over screen content without pushing layout, per standard toast UX — only its `top` offset is computed from `OfflineBanner`'s presence/height as above.

**Timing (D-02):** success auto-dismisses at 3000ms, error at 5000ms, info at 3000ms (treat as success-equivalent timing unless a future phase specifies otherwise). Swipe-to-dismiss (horizontal drag, RN `Animated` + `PanResponder` — zero new deps) available immediately, before the auto-dismiss timer fires; a drag past 80px horizontal releases into a dismiss animation.

**Stacking (D-03):** exactly one toast on screen at a time. Calling `success`/`error`/`info` while a toast is showing **replaces** it immediately (fade/slide the old one out, new one in) — no queue.

**Content (D-04):** `useToast()` returns `{ success(msg: string), error(msg: string), info(msg: string) }`. Each `msg` is a caller-already-translated string — Toast never calls `t()` internally. Toast is **not interactive**: tapping it does nothing (only the swipe gesture dismisses).

**Visual style — solid fill (not the pale `*Soft` pill style used by badges/pills), since a transient 3–5s notification needs higher contrast than a persistent status chip:**

| Variant | Background | Icon | Text |
|---|---|---|---|
| `success` | `#0E7468` (`statusTokens.ready`) | `checkmark-circle`, `#FFFFFF`, size 18 | `#FFFFFF`, 15px/600 |
| `error` | `#A9363F` (`statusTokens.dirty`) | `alert-circle`, `#FFFFFF`, size 18 | `#FFFFFF`, 15px/600 |
| `info` | `#20251F` (`shellTokens.bg`) | `information-circle`, `#FFFFFF`, size 18 | `#FFFFFF`, 15px/600 |

Container: `borderRadius: R.md` (12), `paddingHorizontal: 16`, `paddingVertical: 12`, `flexDirection: row`, `alignItems: center`, `gap: 12`, text allowed to wrap to 2 lines (do not truncate — Spanish strings run 15–30% longer per Pitfall 4). Shadow: `shadowOpacity: 0.18`, `shadowRadius: 10`, `shadowOffset: {0,4}`, elevation 6.

**Motion:** enter — translateY from −20 to 0 + opacity 0→1, 200ms ease-out. Exit (timeout or swipe release beyond threshold) — translateY 0→−20 + opacity 1→0, 150ms ease-in. Implemented via RN core `Animated` API only (no Reanimated/new dependency, per Pitfall 3 / STACK.md).

## i18n Lint Gate (I18N-01)

- Hard CI failure (D-16), not a warning — mirrors web's `i18next/no-literal-string` gate exactly.
- Scope (D-15): `components/ui/` (the 4 new primitives) **plus** the existing floor-facing screens/components: `app/(app)/my-rooms/**`, `room-board/**`, `room-status/**`, `work-orders/**`, `tasks/**`, `inspect/**`, and their feature-component equivalents in `components/housekeeping/`, `components/engineering/`, `components/tasks/`. Non-floor screens are explicitly out of scope this phase (added gate-by-gate in Phase 9).
- Corollary for the primitives contract above: every string prop documented in this spec (`label`, `title`, `message`, toast `msg`) is a caller-supplied translated value — the primitives themselves contain zero literal JSX strings, so they trivially pass the new gate on day one.

## Copywriting Contract

Phase 7 ships no user-facing screen — there is no real empty/error data to author copy for yet. This section defines the **copy contract shape** every primitive enforces, plus reference examples for Phase 8+ to follow, and the shared i18n key convention this phase should seed.

| Element | Copy |
|---------|------|
| Primary CTA | N/A this phase (no screen ships new user-facing copy). The one concrete CTA the primitives themselves surface is `StateBlock`'s optional retry action — reference default label: **"Try again"** / ES **"Reintentar"**, suggested key `common.retry`. |
| Empty state heading | Caller-supplied, required prop. Shape: ≤4 words, names what's missing (e.g. "No rooms assigned" — illustrative only, not shipped this phase). |
| Empty state body | Caller-supplied, required prop. Shape: one sentence naming the cause or next step (e.g. "Rooms will appear here once assigned for today." — illustrative only). |
| Error state | Caller-supplied, required prop. Shape: problem + implicit next step via the adjacent retry button (e.g. "Something went wrong loading this data." / ES "Ocurrió un error al cargar estos datos." — suggested seed keys `common.errorGeneric.title`/`.body`). |
| Destructive confirmation | N/A this phase. `Button`'s `destructive` variant is styling-only — no confirmation dialog is wired by any Phase 7 primitive. Any screen that pairs `variant="destructive"` with a real destructive action (Phase 8/9) must supply its own confirmation step per existing project convention; not defined here. |

Suggested i18n keys to seed in EN+ES this phase (used by the primitives' own tests/storybook-equivalent, not yet by any screen): `common.retry`, `common.loading`, `common.errorGeneric.title`, `common.errorGeneric.body`.
