<objective>
Ship the scoped, tractable fix for bug-965 (the `domTranslations.ts` legacy DOM-translator hybrid-mangling defect, confirmed recurring 3x across Phases 34/35/36 and deliberately deferred each time), and commit a permanent Playwright regression spec so this defect class is never silently rediscovered again.

37-RESEARCH.md traced the exact mechanism: `REVERSE_TRANSLATIONS` (Spanish→English) is built from the FULL flattened `en.ts`/`es.ts` locale tree, but the forward direction (English→Spanish) only uses the SMALL curated `PHRASE_TRANSLATIONS` (~250 entries) plus a crude per-word `GLOSSARY_TRANSLATIONS` regex fallback. When a freshly-mounted DOM text node (e.g. a `StateBlock` error that only mounts once a query settles into `isError`) already holds the exact, correct `es.ts` value, the reverse lookup recovers the exact English original — then re-forward-translates it through the SMALL dictionary instead of the SAME full dictionary it was recovered from, producing hybrids like `"Couldn't load your Suscripcion."` The fix: give the forward direction the same full-dictionary lookup the reverse direction already has, so the round-trip is lossless. This is CONTEXT.md's locked mandate — Phase 37 is the dedicated closing gate for this defect and must not defer it a 4th time.

Purpose: close a 3x-confirmed, previously-deferred defect with a small (~10 line), single-file, zero-call-site-change fix, and convert 5 phases' worth of manual rediscovery into a permanent CI gate.
Output: `domTranslations.ts` fixed; `apps/web/e2e/i18n-dom-translator.spec.ts` + `apps/web/playwright.i18n.config.ts` committed and green; `.wolf/buglog.json`'s bug-965 entry updated to `fixed`.
