  <name>Task 2: Add select-args capture to FakeDB + regression test for the id field</name>
  <files>apps/api/tests/smoke/fake_supabase.py, apps/api/tests/test_ai_copilot_rbac.py</files>
  <action>
Problem: `apps/api/tests/smoke/fake_supabase.py`'s `FakeQuery.select(self, *_args, **_kwargs)` currently discards its arguments and `FakeQuery.execute()` always returns full matched rows regardless of what columns were selected — real Supabase/PostgREST restricts returned columns to the select list, but this fake doesn't simulate that. A naive test that seeds a row with `id` and asserts the response contains `id` would pass whether or not Task 1's select change exists, because the fake ignores select() entirely. This is not a safe regression test on its own.

Fix (mirrors the existing, working pattern in `apps/api/tests/smoke/test_housekeeping_assignments.py`'s local `FakeQuery.select_args` / `select_calls`-by-string-membership convention — reuse that idea here instead of inventing a new one):

1. In `apps/api/tests/smoke/fake_supabase.py`:
   - In `FakeDB.__init__`, add: `self.select_calls = []`
   - In `FakeQuery.select`, change:
     ```python
     def select(self, *_args, **_kwargs):
         self.action = "select"
         return self
     ```
     to:
     ```python
     def select(self, *args, **_kwargs):
         self.action = "select"
         self.db.select_calls.append((self.table_name, args))
         return self
     ```
   This is purely additive — no existing test reads or depends on the absence of `select_calls`, so nothing else in the suite can regress from this change.

2. In `apps/api/tests/test_ai_copilot_rbac.py`, add a new test function (near the other `/ai/risk-alerts`-adjacent coverage, using the existing `FakeDB` import from `tests.smoke.fake_supabase` and the existing `_user()` helper already defined in this file):
   ```python
   @pytest.mark.asyncio
   async def test_risk_alerts_asset_select_includes_id(monkeypatch):
       """AI-08: /ai/risk-alerts must select+return `id` on assets so the
       frontend can build a maintenance deep link. Asserts the select-string
       itself (not just the echoed row) because FakeDB does not enforce
       column projection like real PostgREST does."""
       db = FakeDB({
           "assets": [
               {"id": "asset-1", "tenant_id": "hotel-1", "name": "Boiler", "failure_risk_score": 85},
           ],
       })
       monkeypatch.setattr(ai_copilot, "supabase", db)

       response = await ai_copilot.get_risk_alerts(current_user=_user("gm"))

       assert response["data"]["maintenance_risks"][0]["id"] == "asset-1"
       asset_select_args = next(args for table, args in db.select_calls if table == "assets")
       assert "id" in " ".join(str(a) for a in asset_select_args)
   ```
   Place it near `test_open_endpoints_accept_any_role` or another `/ai/risk-alerts`-related section for discoverability. Do not modify any other existing test in this file.
  </action>
