<objective>
Build the frontend half of ARCHIVE-01 through ARCHIVE-06 on top of Plan 15-01's three new backend endpoints (`POST /work-orders/bulk-archive`, `POST /work-orders/bulk-archive-by-age`, `POST /work-orders/bulk-unarchive`) and its `archived` query param on `list_work_orders`.

Per 15-RESEARCH.md Pattern 5 and Open Question 2: the existing 5-column Kanban board (`work-orders/page.tsx`) never renders a "Cancelled" column and should not be reshaped to fit a manager-only, occasional bulk-archive action. Instead, bulk-archive selection lives in its own modal (`BulkArchiveModal`, reachable via a new "Archive..." action button), and restoring lives in a new third page tab ("Archived", reusing the existing `activeTab` + `PageHeader.tabs` pattern already used for "Room Board").

Purpose: give managers a way to declutter the active board and later find/restore anything they archived, without touching the Kanban's existing 5 columns or its Realtime wiring.

Output: extended API client, two new components, a third page tab, an "Archive..." entrypoint, and EN/ES locale parity for all new copy.
</objective>
