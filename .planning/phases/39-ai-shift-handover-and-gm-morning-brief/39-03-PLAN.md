**Locked decisions from 39-CONTEXT.md:**
- Endpoint path: `POST /v1/logbook/shift-summary/{summary_id}/acknowledge` (the logbook router is mounted at prefix `/v1/logbook`, so add `@router.post("/shift-summary/{summary_id}/acknowledge")`). Auth: `get_current_user` only — NO `require_role`. Any authenticated role may acknowledge.
- On acknowledge: load the row by `id = summary_id` AND `tenant_id = current_user.hotel_id` (tenant scope is mandatory per CLAUDE.md multi-tenancy — never acknowledge cross-tenant). If not found → 404. If `acknowledged_at` is already set → return the existing acknowledgment unchanged (idempotent 200, do NOT overwrite `acknowledged_by`/`acknowledged_at`, do NOT 409). Otherwise `update({"acknowledged_by": current_user.user_id, "acknowledged_at": now_iso})` scoped by id + tenant_id.
- `GET /logbook/shift-summary/{shift_id}` (existing, currently `select("*")` so it already returns the raw columns) must additionally return a resolved `acknowledged_by_name` (null when `acknowledged_by` is null). Extend the response — do not remove `summary_text` or any existing field.
- Name resolution: reuse this codebase's existing `user_profiles` lookup pattern (grep for how `full_name`/`preferred_name` is fetched — e.g. `internal.py`'s gm_profile lookup, or the `user_profiles(preferred_name, full_name)` join in logbook entries). Prefer `preferred_name` then `full_name`, matching the logbook EntryCard convention (`preferred_name ?? full_name`). Do NOT add a new profile-lookup helper if one already exists — reuse it.
- Idempotent response shape is Claude's discretion (silent no-op returning the row, or an added `"already_acknowledged": true` flag). Whichever you pick, the acknowledge response SHOULD return the row's `id`, `acknowledged_by`, `acknowledged_at`, and `acknowledged_by_name` so the UI can render immediately without a refetch.

**Response envelope:** follow the repo convention `{"data": ...}` (the existing `get_shift_summary` returns `{"data": result.data}`).

**Web client note:** `getShiftSummary`'s current return type is `{ summary_text: string; generated_by_ai: boolean }` — it must be extended (not replaced) to add `id: string`, `acknowledged_by: string | null`, `acknowledged_at: string | null`, `acknowledged_by_name: string | null`. Add `acknowledgeShiftSummary: (summaryId: string) => apiClient.post(...)` returning the same acknowledgment shape.
