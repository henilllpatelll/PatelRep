<objective>
Close UX-01: staff display names never render blank anywhere in the app; a fallback displays when name data is missing.

Root cause (confirmed by direct read this session): `apps/api/routers/staff.py:136` uses `profile.get("full_name", "")` — Python's `dict.get(key, default)` only substitutes `default` when the key is **absent**, not when it exists with value `None`. A `user_profiles` row with a NULL `full_name` (e.g. a staff member added via direct-add before setting a name) serializes as `"full_name": null` in the API response. Every other full-name lookup in this codebase already uses the safe `.get(key) or default` pattern (`housekeeping.py`, `reports.py`, `programs.py`) — `staff.py:136` is the one outlier.

That `null` then reaches 3 independent, duplicate, unguarded local copies of `getInitials(name: string)` (`staff/page.tsx:92-98`, `scheduling/page.tsx:103-110`, `housekeeping/page.tsx:156-158`, all calling `name.split(' ')` with no null guard) plus several raw renders/splits/searches of `.full_name` — all of which throw `TypeError: Cannot read properties of null (reading 'split')` today given a NULL-named profile.

Purpose: eliminate the crash risk at its source (backend), then consolidate the 3 duplicate frontend helpers onto one shared, null-safe implementation with a real visible fallback (not just an empty string, which still renders as blank per UX-01's literal wording).

Output: `staff.py` no longer leaks `null`; `lib/utils/avatar.ts` gains a null-safe `getInitials` + new `getDisplayName` helper; all 3 duplicate local `getInitials` functions are deleted and replaced with the shared import; every render/split/search site that touches `.full_name`/`.name` without a guard is fixed to use `getDisplayName`.
</objective>

    Frontend: In `apps/web/lib/utils/avatar.ts`, make `getInitials` null-safe and add a new exported `getDisplayName` helper:
    ```ts
    export function getInitials(name?: string | null): string {
      if (!name) return ''
      return name
        .split(' ')
        .filter(Boolean)
        .slice(0, 2)
        .map((part) => part[0].toUpperCase())
        .join('')
    }

    export function getDisplayName(name?: string | null, fallback = 'Unnamed Staff'): string {
      const trimmed = name?.trim()
      return trimmed ? trimmed : fallback
    }
    ```
    Keep `getAvatarColor` unchanged (it already only receives strings from call sites that will now go through `getDisplayName` first — no null risk there once Task 2 lands).
