### What "verified" means now, and what is retained
* **Scope of the interrupted-unit gate:** it exists in the HOST RUNNER only. The engine path (`runTestUnits`) still gates only `running` units through the `verifyUnitStopped` adapter and re-runs `interrupted_*` units without a new proof; its adapters are simulated, so nothing there owns a host process, and the fields now kept on interruption are not used there. The kept fields are written by the shared `recordOutcome`, so a live adapter that records a workload would inherit them (G-LIVE-RECOVERY-ADAPTERS).
* **Retained:** simulated automatic recovery (the engine's `verifyUnitStopped` adapter contract is unchanged); automatic resumption of a unit whose recorded workload is OBSERVED gone (`WORKLOAD <unit> → observed_stopped`); the ordinary kill of the directly spawned, currently owned test child through its handle; the lock, heartbeat and identity records.
* **`observed_stopped` is an observation of the RECORDED set, not containment.** A descendant that started and double-forked between two snapshots (0 ms, 700 ms, then every 8 s), a process started outside the tree or with a spoofed parent, and a hostile same-user rewrite of the state file are not covered (R-16 is unchanged and stays open). It is not "verified containment" and is not evidence that live autonomous recovery works.
* **Deliberate restriction and its cost.** A survivor of an interrupted unit now stops the runner until a human stops it (or it exits); an interrupted unit that never recorded a workload identity (it died in the first ~1–2 s, before the first process-table read finished, or the table was unreadable) is held until the operator attests; on non-Windows hosts every interrupted unit holds. This costs unattended throughput on purpose: without the recorded identity the runner cannot say what it would be killing.
* **Carried forward (G-LIVE-RECOVERY-ADAPTERS):** OS-ENFORCED workload containment (a Job Object per unit with kill-on-close, or the D3.3 VM guest-user kill) before ANY automatic termination of a recovered process is reintroduced, and robust unattended exclusion (a kernel-lifetime exclusive handle replacing file lock + liveness inference). No further polling heuristics were added.
