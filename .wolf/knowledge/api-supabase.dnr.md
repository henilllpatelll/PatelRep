- [K-7e317f9cff · L465 · 2026-08-05] [2026-08-05] **Starlette/FastAPI middleware order: `CORSMiddleware` must be the OUTERMOST middleware (added LAST via `add_middleware`), never wrapped inside anything that can short-circuit (rate limiting, auth gates, etc.).** `add_middleware` is LIFO — the last-registered middleware becomes outermost. If e.g. a rate-limiter is registered AFTER (outside) CORS and returns an early response without calling `call_next()`, CORS's header-injection dispatch is never entered for that response, so the client gets zero `Access-Control-*` headers. Browsers cannot distinguish "missing CORS headers" from "an actual CORS violation" and report the same opaque "blocked by CORS policy" console error for both — hiding the real status code (429, etc.) from the frontend entirely. `apps/api/main.py` had this backwards (CORS innermost) for the life of the project; fixed in Phase 20-02 (bug-770) by reordering to RateLimit → CORS → SecurityHeaders (innermost → outermost).
